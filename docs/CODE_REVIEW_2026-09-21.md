# 当前代码审阅与整改清单

> 审阅日期：2026-09-21。范围：backend、frontend/src、依赖与部署配置。
> 依据：当前工作区源码静态阅读，以及本地 Chroma 源码的接口核对。没有启动业务服务、连接数据库或请求模型 API。
> 下列行号是审阅时快照，修改代码后会变化；按函数名定位更稳妥。
> P1 = 影响基础正确性、身份隔离或主流程，应优先整改；P2 = 影响稳定性、检索解释和部署体验。

先阅读 [项目方向](PROJECT_DIRECTION.md)，再按 [实施计划](superpowers/plans/2026-09-21-project-remediation.md)逐项完成。本文是问题记录，勾选应以实际测试结果为依据。

## 已有基础值得保留

- User 与 Person 已经使用不同 Neo4j 标签，不需要把两种实体强行合并。
- JWT 解码固定算法，`get_current_user` 会回查账户；需要把它接入业务接口。
- 精确、前缀和语义查询已有部分 owner 过滤；关系更新/删除已有边 owner 条件。
- 已有六个 LangGraph 节点、工具注册表、规则称谓、人物向量与基本前端。
- 新增人物已有补偿思路，LLM 封装已使用 Langfuse 包装客户端。

这些基础可渐进改造。问题在于部分层之间的接口与约束没有同步，不需要先重写整个项目。

## R01 · P1：聊天接口尚未接入认证，身份取自请求体

**证据：** `backend/routers/chat.py:15,64`；`backend/models/schemas.py:16`。路由没有 `Depends(get_current_user)`，把 `request.user_id` 作为工具归属来源。

**触发与影响：** 前端传 token 并不等于后端已经校验。请求可指定任意 user_id，已有可读路径会以该身份查询。不能依赖页面登录状态形成服务端隔离。

**整改：** ChatRequest 只接受消息、会话 ID、请求 ID；用户身份来自认证依赖。客户端提交身份字段应拒绝。所有工具使用独立的可信 RequestContext。

**验收：** 无 token、失效 token 不能触发 Agent；A token 携带 B 的 user_id 被拒绝；A 的合法请求只能获得 A 的数据。缺 token 返回 401 需要显式处理当前 HTTPBearer 的行为，不仅替换函数签名。

## R02 · P1：本人 Person 映射缺失

**证据：** `backend/auth.py:112` 的注册函数只创建 User；`backend/tools/query.py:29` 需要 from_person_id；`backend/tools/definitions.py:168` 没有声明起点。

**触发与影响：** 新用户询问“我和某人什么关系”时，没有可靠的本人 Person 起点。账户 UUID 不是 Person ID。

**整改：** 注册事务创建 User、本人 Person 与 self_person_id 关联；已有账号缺关联时进入绑定/初始化流程。本人查询由服务端解析起点，不让模型猜本人 ID。

**验收：** A、C 分别维护 B；重复初始化不生成第二个本人；新账号录入父亲后可查询本人到父亲的关系；不能绑定其他 owner 的 Person。

## R03 · P1：数据库签名已变化，调用方仍漏传 owner_id

**证据：** `backend/db/neo4j_client.py:401` 定义 get_person_detail(driver, person_id, owner_id)，但 `:111,149,266,270,477` 以及 `backend/tools/person.py:136` 仍使用旧调用。

**触发与影响：** 更新人物、删除人物、添加关系及 person_exists 等路径会出现参数错误。新增人物的向量写入失败时，补偿删除也会进入错误路径。

**整改：** 统一仓储接口，以关键字显式传 owner_id、person_id。包括补偿和手工示例在内，检查全部调用链。

**验收：** 使用假的数据库会话测试参数传递；再用独立测试数据库验证合法 CRUD。不要只补一个调用点，留下补偿路径。

## R04 · P1：owner 约束在数据库边界仍有缺口

**证据：** 人物更新 `neo4j_client.py:126`、删除 `:156`、关系创建端点 `:279` 只匹配 ID；关系旧值查询 `:328` 无 owner；路径 `:368–370` 未检查中间人物；详情 `:422` 与列表 `:454,463` 未约束邻接人物归属；向量删除 `chroma_client.py:119` 无 owner 参数。

**影响边界：** 部分写路径目前先被 R03 的 TypeError 阻断，不能据此声称已验证成功越权写入。修复签名时必须同时补齐写入条件。历史脏边则可能影响路径和邻接资料读取。

**整改：** 读取和写入的 Cypher 同时约束资源、端点及每个中间节点/边的归属。写入在同一事务中匹配与修改，检查实际匹配数量。向量操作使用复合 ID 与 owner 条件，并回查权威档案。

**验收：** 双账号交叉 ID 的读、改、删、建关系、查路径、向量删除均拒绝；人为植入异主中间节点的测试图不能返回该路径。

## R05 · P1：工具定义、注册和实现存在契约漂移

**证据：** `definitions.py:214` 是 list_person_relations，`registry.py:27` 是 list_relations；路径工具缺起点见 R02；`definitions.py:185–191` 声明可选字符串路径，但 `kinship.py:96,107` 需要非空对象列表。

**触发与影响：** 模型即使严格照工具描述输出，也可能收到未知工具、缺参或类型错误。

**整改：** 先统一名称及参数，再以一个 ToolSpec 生成注册表和模型可见 schema。亲属工具对模型只接受 target_person_id，内部查询证据路径，避免让模型编造路径。

**验收：** 全量工具名称集合一致；每个工具的最小合法输入都能通过参数校验并到达对应 handler；owner、确认授权不能成为模型参数。

## R06 · P1：计划不能消费前一步工具结果

**证据：** `plan_tasks.py:29–37` 一次生成列表；`execute_tools.py:18–28` 直接执行，不回传观察结果再规划。

**触发与影响：** 找到或新建人物后，后一步仍使用预先生成的参数；多名同名人物也不能可靠中止修改。

**整改：** 一轮规划一个下一步决定；工具结果携带 call_id、tool、data，进入观察列表。模型据此决定继续、追问或结束。设步数和时间上限。

**验收：** 假工具返回随机人物 ID，后一步使用该 ID；同名两人时停止写入并澄清；轮数耗尽返回已有结果和未完成原因。

## R07 · P1：确认尚未形成服务端授权边界

**证据：** `plan_tasks.py:35` 记录 needs_confirmation，但执行器不检查；`graph.py:34–39` 未注册确认节点；`confirm_action.py:25` 未实现；`person.py:187` 仅检查模型参数的真假值。

**触发与影响：** 模型提供 confirmed=true 或字符串 "false" 都可能越过当前工具层的真假值检查。现有删除路径另受 R03 阻断；修复后不能把这个问题遗留。

**整改：** 服务端保存待确认动作，绑定 owner、thread、动作类型、参数摘要、版本和有效期；独立确认接口消费一次性动作。取消、过期、重复确认有明确状态。

**验收：** 模型 confirmed=true 不触发写入；换用户、换会话、改参数、过期均失败；合法确认只产生一次效果。不要承诺跨存储 exactly-once，用稳定操作 ID 与幂等写入恢复。

## R08 · P1：当前多轮对话上下文没有贯通

**证据：** `frontend/src/api/chat.js:5–9` 不发 history；服务端默认空列表；即使传入，主要由 classify_intent 消费，提取/规划仍只读取当前输入；图编译未配置持久检查点。

**触发与影响：** “张三是老师”后补充“他喜欢钓鱼”、选择同名人物、接续确认都不可靠；刷新页面丢失显示历史。

**整改：** 服务端归属明确的 thread 和消息记录；共享已解析人物、澄清状态、待确认动作。加载 thread 前鉴权；检查点 ID 不能替代归属检查。

**验收：** 代词、同名选择和确认能续接；刷新/重启可恢复；用另一个账号的 thread_id 不能获得历史。

## R09 · P1：合法 JSON 未做结构校验

**证据：** `classify_intent.py:36–37` 直接读键及转 float；`plan_tasks.py:34` 可能保存 None；`execute_tools.py:14,19–20` 直接迭代、访问键。

**触发与影响：** `{}`、null、错误置信度或不完整工具参数会变成异常，而非可恢复的模型输出错误。max_depth、limit 当前还用于字符串拼接，必须先限制为可信整数。

**整改：** Pydantic 校验意图/决定/工具参数，拒绝未知字段；校验后才调用工具。一次有限修复或清晰失败，不能无限重试。

**验收：** 空对象、null、字符串布尔、未知工具、超大深度、越界 limit 均不触发未授权写入或裸异常。

## R10 · P1：错误结构不统一，重试缺少副作用边界

**证据：** `registry.py:46,51` 返回 message，执行器 `:30` 读取 msg；依靠“缺少/已存在”文字判断重试；`generate_response.py:24` 只传成功结果。

**影响：** 错误内容丢失；不可重试错误重复执行；依赖步骤可能继续；部分失败无法完整呈现。

**整改：** 统一 ToolResult(ok, code, message, data, retryable, call_id, tool)；区分校验、归属、歧义、冲突、暂时性故障。读操作或有幂等保证的写操作才允许重试，回复包含部分完成状态。

**验收：** 前一步失败后不继续依赖写入；写入后响应丢失的重试不新增重复人物；部分成功必须明确未完成内容。

## R11 · P1：称谓路径、方向与年龄处理不可靠

**证据：** `kinship.py:12–19` 固定反向映射；`:150–167` 默认取哥/姐；`:130–144` 规则外调用模型并报告成功；`neo4j_client.py:365` 混合关系最短路径；`:389–395` 路径缺稳定 ID 和人物属性。

**整改：** 分离存储方向与遍历方向；反向时使用正确人物性别；先筛亲属边，再有界枚举候选；规则分类与年龄比较分开。未知、冲突、超范围与搜索截断显式返回。

**验收：** 用户指定链的堂哥/堂弟/堂姐/堂妹；未知年龄、同年、未知性别；朋友直连同时存在；关系反向存储；异主节点；多路径冲突与截断。详见骨架和计划测试矩阵。

## R12 · P1：图与向量缺少可恢复的同步状态

**证据：** `chroma_client.py:63` 先删后增；`person.py:149–162` 更新图后写索引；新增补偿依赖当前有问题的删除链。

**影响：** 向量写失败可能留下图与索引不一致；盲目重试整个新增操作可能重复建档。更新故障路径在 R03 修复后也需要验证。

**整改：** 图中的业务记录为权威数据，记录版本和 index_status；写入与待同步标记在同一图事务内提交；索引采用稳定 ID / upsert，成功后按版本标记。更正后查询回查事实状态，旧索引命中也不能复活旧事实。

**验收：** 模拟 embedding、索引写入失败；业务事实不丢失，待同步任务可重放；旧任务不能覆盖新版本。

## R13 · P2：列表与检索的具体契约问题

- `neo4j_client.py:459` 筛选关系分支漏绑定 owner_id；传 relation_type 时出现查询参数错误。
- `neo4j_client.py:222` 模糊查询用 single()，返回单条 Record/None；同名选择需要列表，零条应为 []。
- 精确匹配也只返回第一条，不能把姓名视为唯一标识。
- `neo4j_client.py:318–322` 关系更新未检查匹配数量，零修改仍返回 True。
- `chroma_client.py:24` 未设置距离空间，`:113` 把 1-distance 标为 similarity；当前本地 Chroma 默认 l2，这个数值不能当作余弦相似度。
- `build_person_text` 遍历包含 note 的字段表，但 EMBEDDING_FIELDS 不含 note，修改 note 后可能不重建包含 note 的旧向量。

**整改：** 统一搜索返回 `items: list`；显式说明匹配模式；先修参数和更新数量。距离保留 metric+distance，或新建明确 cosine 的索引并重建；不要仅修改已有集合标签。统一构造文本与重建字段集合。

**核对过的非问题：** 当前本地 Chroma 的 api/types.py 接受一维 list[float] 并进行标准化，不能把 query_embeddings 的一维输入列为确定错误。

## R14 · P2：请求阻塞与资源生命周期

**证据：** async chat 中同步 invoke；同步模型/embedding 调用；多个工具创建 driver 后不关闭；`generate_response.py:10` 在导入时创建闲置客户端。

**整改：** 最小阶段保留同步调用链，将路由改为同步 def 交由框架线程池；资源由应用生命周期创建和关闭。原来的每请求 driver.close 要同步调整，不能关闭共享 driver。之后确需异步时全链验证，单改为 ainvoke 不保证同步 I/O 不阻塞。

**验收：** 假慢模型请求期间健康接口能响应；并发有上限；正常及异常路径资源释放；关闭应用时客户端被关闭。性能上限通过测量描述。

## R15 · P2：前端请求、身份显示与部署地址

**证据：** Chat.jsx:20 没有同步发送锁；输入框 Enter 可重复触发；api/chat.js 信任 localStorage 身份；登录响应没有 phone，但页面读取 user.phone；api/client.js:4 固定 localhost:8000。

**整改：** 前端只发送服务端契约字段，登录后调用现有 /auth/me；同会话先串行发送，按 request_id 关联消息；失败保留重试状态。使用环境配置/同源 /api 路径，展示来源引用与待确认动作。

**验收：** 快速双 Enter 不出现意外并发；延迟回复不串消息；换账号清空本地会话选择；手机访问部署地址时不请求手机自己的 localhost。
