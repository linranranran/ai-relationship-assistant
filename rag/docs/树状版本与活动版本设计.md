# 树状文档版本与活动版本

用户要求直接制定计划并实现。本设计沿用单机、单索引写入者、持久 Inbox 与不可变查询快照，不新增知识模块前端。

## 语义

- document_id 是整棵树的稳定身份；version_id 是不可变版本 ID（整数 ID 接收后规范为字符串），不用于排序。
- parent_version_id 表示来源，不表示活动版本。每版引用完整不可变文件，不使用二进制增量补丁。
- document_revision 是知识模块每次操作提交时生成的递增正整数。新增、激活历史版本、删除均递增；不能用 version_id、树深度或消息到达时间替代。
- 例：10(root)→11→12，10→13；创建13为 revision=4，之后激活12为 revision=5。latest_version_id 仍为13，desired/active_version_id 可以是12。
- 新建版本默认选中该版本；用户手动选择保持到下一次新建或切换。知识模块必须在事务中产生修订与 Outbox。
- desired 是用户选择，active 是已发布索引；目标失败时保留旧 active，状态明确显示待切换/失败。

## 方案选择

不覆盖历史向量，也不把所有版本混入默认检索。采用独立版本目录 + 单独活动指针：创建事件允许历史版本归档，激活已完成版本复用 generation，仅重建完整知识库 BM25/快照。每个版本一个独立集合会增加集合和查询管理成本；原地覆盖会失去快速切换与失败隔离。

## schema_version=2 事件

共有 schema_version、event_id、event_type、tenant_id、knowledge_base_id、document_id、document_revision，可选 trace_id/occurred_at。

1. document.version.created：version_id、parent_version_id（root 可空）、version_label 可选、file_name、object（bucket/key/sha256，OSS version_id 可选）。不可变版本禁止重用 ID 改内容/父节点/创建修订。
2. document.version.activated：version_id；不携带文件对象。目标创建消息未到时持久等待，不消耗模型失败次数，默认等待上限3600秒；超时死信，人工修复后重试。
3. document.deleted：删除整份逻辑文档，不携带版本/对象；墓碑阻止旧操作复活。删除状态下激活拒绝；新的更高 revision 的创建可恢复文档。单独删除某个历史版本暂不提供，避免猜测替代活动版本或破坏父链。

所有操作以(scope,document_id,document_revision)去重，同修订不同语义冲突。schema1 保持原功能；同一逻辑文档不混用两种协议。旧 receipt 的重复消息仍可幂等确认，已有 schema1 文档转成树需要明确映射/新逻辑 ID，本次不猜测迁移关系。

## 持久化与并发

- 追加 document_versions：scope/doc/version_id、parent、label、creation_revision、不可变创建 payload/指纹、ready generation。
- 追加 version_heads：latest 创建版本/修订、desired 版本/操作修订、active 版本/操作修订、desired_deleted。
- 原 jobs.version 在 schema2 中保存 document_revision；原 heads 保存共同活动 generation，使 schema1/2 的不同文档可以处于同一个知识库快照。
- 建表使用增量迁移，不清空已有 SQLite、快照或节点。
- 创建旧版本仍可归档成功，但发布只在 desired_revision 与 desired_version_id 同时匹配时执行。旧激活操作标记 superseded。
- generation 按不可变版本与模型/管道配置产生；复用前验证节点完整并恢复 Redis 镜像，不访问 OSS 或 Embedding。
- 已 ready 的版本必须读取目录登记的 generation；当前配置不兼容时明确失败，不隐式重建历史索引。状态接口直接提供 desired 操作的 event_id/status/error，不依赖全局最近任务列表。
- 默认查询仍只包含每文档一个 active generation。来源附 version_id/parent_version_id/version_label；切换前在途查询可继续使用旧快照。
- 父元数据可以晚到，完整子文件可独立索引。已知边要求父创建修订早于子创建修订，拒绝自引用/成环与多个根；缺失父节点在树接口显式标记。

## 交付与验收

提供只读版本树/选择状态 API、MQ 模拟新版本/激活/删除/重放脚本和联调指南。知识模块界面操作仍通过其自己的业务事务与 MQ 完成，RAG 不提供绕过事件的写接口。

重点验证用户的10/11/12/13例子；手动12↔13重复切换；旧消息与慢构建不回退选择；激活先到、创建后到；缓存复用；失败保持旧快照；删除墓碑；协议兼容/升级；不同租户与其他文档不受影响。真实 RabbitMQ 验证消息流程，离线确定性向量验证索引机制；不冒称真实 OSS/模型已端到端验证。
